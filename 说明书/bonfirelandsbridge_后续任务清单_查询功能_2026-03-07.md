# bonfirelandsbridge 后续任务清单: 查询功能

日期: 2026-03-07
状态: 查询功能一期已在 v0.3.0 实现
目标版本: v0.3.0 已完成一期

## 1. 新增需求总览
需要在 bonfirelandsbridge 中补一组“租赁信息查询”能力，方便玩家和管理员查询当前租房状态。

### 玩家侧需求
1. 玩家可以查询自己当前租赁了哪些房屋。
2. 玩家可以看到每个房屋当前还剩多少租赁时间。
3. 如果玩家当前没有租任何房屋，要给出明确中文提示。

### 管理员侧需求
1. 管理员可以查询指定玩家当前租赁的房屋信息。
2. 管理员可以查询全服所有玩家的租赁房屋信息。
3. 管理员查询结果最好能看到:
   - 玩家名
   - 领地名
   - 区域名
   - 剩余时间
   - 当前租户 UUID
   - 是否处于已租状态

## 2. 建议指令方案
### 玩家指令
建议新增:

- `/blb myrent`
  - 查询自己当前租赁的全部房屋
- `/blb myrent detail`
  - 查询自己当前租赁房屋的详细剩余时间

说明:

- 继续沿用 bonfirelandsbridge 自己的 `/blb` 主命令更稳，不需要和 Lands 原生命令抢语义。
- 输出尽量做成中文、短行、多条消息，避免聊天栏太长。

### 管理员指令
建议新增:

- `/blb rentinfo <玩家名>`
  - 查询指定玩家当前租赁信息
- `/blb rentlist`
  - 查询全服当前所有已租房屋
- `/blb rentlist <页码>`
  - 分页查看全服租赁列表

说明:

- 全服列表必须分页，不能一次性把所有数据刷到聊天栏。
- 后续如果数据量大，可以再补导出文件功能，但第一期先不用做导出。

## 3. 查询结果建议展示内容
### 玩家查询
建议每套房屋展示:

- 房屋所在领地: `land`
- 房屋区域名: `area`
- 当前剩余时间: `remaining`
- 当前续租步长: `rent period`
- 当前上限参考值: `base max`

### 管理员查询
建议额外展示:

- 租户 UUID
- 是否命中 bonfirelandsbridge 快照
- 是否存在租户身份异常
- 是否建议执行租户身份自修复

## 4. 技术实现建议
### 数据来源
建议组合两类数据源:

1. Lands API 实时状态
   - 用来确认 area 当前是否处于已租状态
   - 用来确认 tenant 是否存在
2. bonfirelandsbridge 自己的快照/计算逻辑
   - 用来计算剩余时间
   - 用来保持和“剩余时间上限”修复逻辑一致

### 剩余时间计算建议
不要只显示 Lands 原生累计时间。
应该统一按 bonfirelandsbridge 当前运行逻辑来算“真实剩余时间”，否则玩家看到的时间和续租判定可能对不上。

### 性能要求
查询功能必须尽量轻量，避免对生产环境造成额外压力。
建议:

- 玩家查询只查“当前玩家名下租赁区域”
- 管理员全服查询时做分页
- 尽量复用现有 `findTenantAreas`、租赁状态识别和剩余时间计算逻辑
- 不做高频自动轮询，只在玩家执行命令时查询
- 如需全服列表，优先异步整理结果后再回主线程发消息

## 5. 中文提示要求
保持和当前 v0.2.x 一样的中文风格。
提示词统一使用:

- 居民
- 房屋
- 租赁区域
- 剩余时间

尽量避免英文术语直接抛给玩家。
管理员提示可以稍微技术一点，但玩家提示必须白话。

## 6. 验收标准
完成后至少要满足:

1. 玩家执行 `/blb myrent` 时，能看到自己当前租赁的全部房屋。
2. 玩家能看到每套房屋的剩余时间。
3. 无房玩家会收到中文提示，而不是空白输出。
4. 管理员执行 `/blb rentinfo <玩家名>` 能看到指定玩家的租房信息。
5. 管理员执行 `/blb rentlist` 能分页查看全服租房信息。
6. 查询功能不能影响现有续租、trust、untrust 功能。

## 7. 当前结论
这个需求已经纳入 bonfirelandsbridge 后续任务。
下一阶段可以按“查询功能一期”单独开发，不建议和当前线上修复版混发。

已在 v0.3.0 完成一期实现，已落地命令:

- `/blb myrent detail`
- `/blb rentinfo <玩家名>`
