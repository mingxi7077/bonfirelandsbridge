# bonfirelandsbridge 生产排障手册 v0.2.3

位置: bonfirelandsbridge 项目内 说明书 目录
适用版本: v0.2.3

## 1. 这一版主要修什么

v0.2.3 重点修的是这个问题:

- 玩家明明站在自己租的房子里
- 但 `/lands trust <居民名>` 仍然被判定为“不在自己的租赁区域内”

这不是续租问题。
这是 trust 时“当前位置 area 识别偏差”问题。

## 2. 为什么会出现“明明在房里却被判不在房里”

按现在服务器的 Lands 结构:

- 整体是管理员母领地
- 母领地下再划很多 rent 子区域
- 玩家实际住房都挂在这些 rent 区域上

在这种结构里，单纯依赖一次 `getArea(location)` 会有几种偏差:

1. 玩家脚下被识别成母领地默认区域，而不是租赁子区域。
2. 玩家站在边界、楼梯、夹层、角落时，被识别到相邻区域。
3. 当前坐标在视觉上属于房内，但 Lands 当前这次命令上下文没有落到真正的 tenant area。

所以 v0.2.2 的问题不是 trust 权限本身，而是“先用脚下 area 做前置判断”这一步太死。

## 3. v0.2.3 具体怎么修

### 3.1 area 识别从一层改成三层

旧版 v0.2.2:

- 只看一次 `getArea(player.getLocation())`
- 不是租户 area 就直接拦

新版 v0.2.3:

1. 先看脚下直接识别到的当前 area。
2. 如果脚下没识别到自己的租区，就遍历这个居民名下所有租赁区域，按精确坐标再匹配一遍。
3. 如果精确坐标还没命中，再按水平范围做最后一层兜底匹配。

也就是说:

- 不再只信“脚下一次 area 返回结果”
- 会再去扫描这个居民自己名下的租赁区域
- 尽量把“房内误判”纠正回来

### 3.2 trust 不再只交给 Lands 原生命令

v0.2.3 对租户 trust 做了更稳的桥接处理:

- 一旦桥接插件已经成功识别出这个居民真正对应的租赁区域
- 插件会先做租户身份自修复
- 然后直接按识别到的租赁区域完成 trust 和保存

这样做的目的就是:

- 不再把最后一步再交回给 Lands 当前位置判断
- 避免又被 Lands 原生命令的 area 判定卡住

## 4. 玩家现在会看到什么提示

### 4.1 如果系统已经成功识别到真实租区

玩家会直接收到成功提示。
如果这次是通过兜底识别修正出来的，还会额外提示:

- 本次已自动按你的租赁区域处理居民信任
- 已绕过当前位置识别偏差

### 4.2 如果系统还是没识别到

玩家会收到更完整的中文提示:

- 当前未识别到你正站在自己的租赁区域内
- 当前识别区域是什么
- 你名下租赁区域是什么
- 请尽量站在房屋中央或租赁牌附近再试
- 如果确认就在房内，请联系管理员检查房屋边界

这样玩家至少知道:

- 不是命令错了
- 不是居民名一定错了
- 而是当前位置和租赁区域识别没有对上

## 5. 这次改动对现有生产数据有没有影响

没有清档需求，也不需要玩家重租。

v0.2.3 仍然兼容现有:

- 续租时间数据
- 现有 rent 区域数据
- MySQL 快照数据
- base-max-registry.yml

这一版主要是 trust 识别和处理链路更稳，不是重做存量租赁数据。

## 6. 升级方式

1. 只替换 `plugins/bonfirelandsbridge.jar`
2. 保留原有 `plugins/bonfirelandsbridge` 数据目录
3. 不需要新增 MySQL
4. 不需要新增 Redis
5. 建议重启服务器加载，不建议 PlugMan 热加载

## 7. 线上排障时优先看什么

### 7.1 看版本

启动日志里确认:

- `Loading server plugin bonfirelandsbridge v0.2.3`
- `Enabling bonfirelandsbridge v0.2.3`

### 7.2 看 trust 相关日志

v0.2.3 新增了更明确的桥接日志，重点关注:

- `Resolved tenant trust area by fallback`
- `Blocked bridged trust because resident is outside resolved rental area`
- `Failed to save bridged trust grant`

### 7.3 看到 fallback 日志代表什么

如果出现:

- `Resolved tenant trust area by fallback`

就说明:

- 原本脚下直接识别的 area 不可靠
- 但是插件后续通过租户区域扫描把真实租区找出来了
- 这是本次修复在生效，不是报错

## 8. 这一版最重要的一句话

v0.2.3 修的不是“续租”，而是“rent 子区域在 trust 时被当前位置 area 误判”的问题。

以后再遇到类似情况，先不要直接怀疑 trust 权限本身，优先怀疑:

- 当前脚下 area 判错了
- 玩家站在边界/楼层/夹角
- 母领地与 rent 子区域识别冲突
